# RAG 知识库问答系统 - 系统架构设计文档

## 1. 系统概述

### 1.1 项目背景
RAG（Retrieval-Augmented Generation，检索增强生成）是一种结合信息检索和文本生成的技术，通过从外部知识库检索相关信息来增强大语言模型的回答能力。

### 1.2 设计目标
- **准确性**: 基于真实文档生成答案，减少幻觉
- **可溯源**: 答案附带参考来源，便于验证
- **高效性**: 毫秒级检索响应
- **可扩展**: 模块化设计，易于添加新功能

### 1.3 核心特性
- 多格式文档支持（PDF、Word、Markdown、代码文件）
- 混合检索策略（向量检索 + BM25）
- 重排序优化（Cross-Encoder）
- 引用溯源与置信度评估

## 3. 模块设计

### 3.1 文档加载模块 (Document Loader)

**职责**: 负责从不同格式的文件中提取文本内容

**核心类**:
- `BaseDocumentLoader`: 抽象基类
- `PDFLoader`: PDF 文档加载
- `DocxLoader`: Word 文档加载
- `TextLoader`: 文本文件加载
- `DocumentLoaderFactory`: 工厂类

**设计模式**: 工厂模式 + 策略模式

### 3.2 文本分块模块 (Text Splitter)

**职责**: 将长文档切分为适合检索的小块

**核心类**:
- `TextSplitter`: 基础分块器
- `SemanticTextSplitter`: 语义分块器（扩展）

**分块策略**:
1. **递归分块**: 按优先级尝试不同分隔符
2. **字符分块**: 固定字符数切分
3. **Token 分块**: 按 Token 数切分

**关键参数**:
- `chunk_size`: 块大小（默认 500 字符）
- `chunk_overlap`: 重叠大小（默认 50 字符）

### 3.3 Embedding 模块

**职责**: 将文本转换为向量表示

**核心类**:
- `EmbeddingManager`: Embedding 模型管理
- `VectorStoreManager`: 向量数据库管理

**支持的模型**:
| 模型 | 维度 | 语言 | 特点 |
|------|------|------|------|
| BAAI/bge-large-zh | 1024 | 中文 | 效果最佳 |
| BAAI/bge-base-zh | 768 | 中文 | 速度更快 |
| moka-ai/m3e-base | 768 | 多语言 | 通用性强 |

**向量数据库**:
- FAISS: Facebook 开源，性能优秀
- Chroma: 轻量级，易于使用
- Milvus: 企业级，支持分布式

### 3.4 检索模块 (Retriever)

**职责**: 从知识库中检索相关文档

**核心类**:
- `HybridRetriever`: 混合检索器
- `Reranker`: 重排序器
- `AdvancedRetriever`: 高级检索器（整合功能）

**混合检索算法**:
```python
# RRF (Reciprocal Rank Fusion)
score = Σ(1 / (k + rank_i))
```

**检索流程**:
1. 向量检索: 语义相似度匹配
2. BM25 检索: 关键词匹配
3. 结果融合: RRF 算法
4. 重排序: Cross-Encoder 精排

### 3.5 问答生成模块 (QA Generator)

**职责**: 基于检索结果生成最终答案

**核心类**:
- `QAGenerator`: 问答生成器
- `ContextCompressor`: 上下文压缩器

**RAG 提示词模板**:
```
基于以下参考信息回答问题。如果参考信息不足以回答问题，请明确说明。

参考信息：
{context}

用户问题：{question}

请提供准确、简洁的回答，并在回答中标注引用来源。
```

## 10. 总结

本系统采用经典的 RAG 架构，通过模块化设计实现了：
1. **高准确率**: 混合检索 + 重排序优化
2. **低延迟**: 本地向量数据库 + 缓存
3. **易扩展**: 工厂模式 + 插件机制
4. **可溯源**: 引用标注 + 置信度评估

下一步优化方向：
- 引入 Query Expansion 提升检索召回
- 实现多轮对话的上下文管理
- 支持多模态文档（图片、表格）
