## 1. 文档加载模块

### 1.1 设计思路

文档加载模块采用**工厂模式**设计，通过统一的接口支持多种文档格式。核心设计原则：

- **开闭原则**: 新增文档格式只需添加新的 Loader 类
- **单一职责**: 每个 Loader 只负责一种格式
- **依赖倒置**: 上层依赖抽象接口，不依赖具体实现

### 1.2 类图

```
┌─────────────────────────────┐
│  <<abstract>>               │
│  BaseDocumentLoader         │
├─────────────────────────────┤
│ + load(file_path): List[Doc]│
│ + supports(ext): bool       │
└───────────┬─────────────────┘
            │
    ┌───────┼───────┐
    ↓       ↓       ↓
┌────────┐┌────────┐┌────────┐
│PDFLoader││DocxLoader││TextLoader│
└────────┘└────────┘└────────┘
```

### 1.3 核心代码解析

#### 基类定义

```python
class BaseDocumentLoader(ABC):
    """文档加载器基类"""
    
    @abstractmethod
    def load(self, file_path: str) -> List[Document]:
        """加载文档"""
        pass
    
    @abstractmethod
    def supports(self, file_extension: str) -> bool:
        """检查是否支持该文件类型"""
        pass
```

#### 工厂类实现

```python
class DocumentLoaderFactory:
    """文档加载器工厂"""
    
    _loaders: List[BaseDocumentLoader] = [
        PDFLoader(),
        DocxLoader(),
        TextLoader(),
    ]
    
    @classmethod
    def get_loader(cls, file_path: str) -> BaseDocumentLoader:
        """根据文件路径获取对应的加载器"""
        file_extension = Path(file_path).suffix.lower()
        
        for loader in cls._loaders:
            if loader.supports(file_extension):
                return loader
        
        raise ValueError(f"不支持的文件类型: {file_extension}")
```

## 2. 文本分块模块

### 2.1 设计思路

文本分块是 RAG 系统的关键环节，直接影响检索质量。设计考虑：

- **语义完整性**: 优先在句子、段落边界切分
- **上下文保留**: 块之间保留重叠部分
- **灵活性**: 支持多种分块策略

### 2.2 分块策略对比

| 策略 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| 递归分块 | 保持语义完整 | 块大小不均匀 | 通用场景 |
| 固定字符 | 实现简单 | 可能切断句子 | 对格式要求低 |
| Token 分块 | 精确控制长度 | 需要 Tokenizer | 严格长度限制 |
| 语义分块 | 语义连贯 | 计算成本高 | 高精度要求 |

## 3. Embedding 模块

### 3.1 设计思路

Embedding 模块负责将文本转换为向量表示，是语义检索的基础。设计要点：

- **模型管理**: 支持多种 Embedding 模型
- **向量存储**: 支持多种向量数据库
- **性能优化**: 批处理、缓存、GPU 加速

#### VectorStoreManager

```python
class VectorStoreManager:
    """
    向量数据库管理器
    
    职责：
    1. 管理向量数据库的创建和加载
    2. 提供相似度搜索接口
    3. 支持数据持久化

    def create_vector_store(self, documents: List[Document]):
        """从文档创建向量数据库"""
        if self.vector_store_type == "faiss":
            return FAISS.from_documents(documents, self.embedding_manager.embedding_model)
        elif self.vector_store_type == "chroma":
            return Chroma.from_documents(documents, self.embedding_manager.embedding_model)
    
    def similarity_search(self, query: str, k: int = 5):
        """相似度搜索"""
        return self._vector_store.similarity_search_with_score(query, k=k)
```

## 4. 检索模块

### 4.1 设计思路

检索模块是 RAG 系统的核心，直接影响回答质量。采用**多阶段检索**策略：

1. **粗排阶段**: 快速召回候选文档
2. **精排阶段**: 对候选文档进行精细排序

### 4.2 混合检索原理

#### 向量检索
- **原理**: 基于语义相似度
- **优点**: 理解同义词、语义关联
- **缺点**: 对关键词匹配不敏感

#### BM25 检索
- **原理**: 基于词频和逆文档频率
- **优点**: 精确的关键词匹配
- **缺点**: 无法理解语义

#### RRF 融合算法

```python
def reciprocal_rank_fusion(results_list, k=60):
    """
    RRF 融合算法
    
    公式: score = Σ(1 / (k + rank_i))
    
    参数:
        k: 常数，控制低排名的影响，通常取 60
        rank_i: 文档在第 i 个结果列表中的排名
    """
    scores = {}
    
    for results in results_list:
        for rank, doc in enumerate(results):
            doc_id = get_doc_id(doc)
            if doc_id not in scores:
                scores[doc_id] = {"doc": doc, "score": 0}
            scores[doc_id]["score"] += 1.0 / (k + rank + 1)
    
    # 按分数排序
    return sorted(scores.values(), key=lambda x: x["score"], reverse=True)
```

### 4.3 重排序原理

Cross-Encoder 重排序：

```python
class Reranker:
    """
    重排序器
    
    原理：
    1. 将查询和文档拼接为 [CLS] Query [SEP] Document [SEP]
    2. 输入 Cross-Encoder 模型
    3. 输出相关性分数 (0-1)
    
    优点：
    - 比 Bi-Encoder 更精确
    - 考虑查询和文档的交互
    
    缺点：
    - 计算成本高，只能用于精排阶段
    """
    
    def rerank(self, query: str, documents: List[Document], top_k: int = 5):
        # 构建输入对
        pairs = [[query, doc.page_content] for doc in documents]
        
        # 编码并预测
        inputs = self.tokenizer(pairs, padding=True, truncation=True, return_tensors='pt')
        scores = self.model(**inputs).logits.view(-1).float()
        scores = torch.sigmoid(scores).cpu().numpy()
        
        # 排序
        doc_scores = list(zip(documents, scores))
        doc_scores.sort(key=lambda x: x[1], reverse=True)
        
        return doc_scores[:top_k]
```

### 4.4 检索流程图

```
用户查询
    │
    ├──→ 向量检索 ──→ Top 10 ──┐
    │                          ├──→ RRF 融合 ──→ Top 10 ──→ Cross-Encoder 重排序 ──→ Top 5
    └──→ BM25 检索 ──→ Top 10 ─┘
```

### 5.3 上下文构建策略

```python
def _format_context(self, documents: List[Document], max_length: int = 4000):
    """
    格式化上下文
    
    策略：
    1. 按相关性排序
    2. 添加来源标记
    3. 截断超长内容
    4. 保留关键信息
    """
    context_parts = []
    current_length = 0
    
    for i, doc in enumerate(documents):
        source_info = f"\n[来源{i+1}] {doc.metadata.get('file_name', '未知')}\n"
        content = doc.page_content
        
        # 截断策略
        if current_length + len(content) > max_length:
            remaining = max_length - current_length
            if remaining > 100:
                content = content[:remaining] + "..."
                context_parts.append(source_info + content)
            break
        
        context_parts.append(source_info + content)
        current_length += len(source_info) + len(content)
    
    return "\n".join(context_parts)
```

### 5.4 置信度计算

```python
def _calculate_confidence(self, documents: List[Document]) -> float:
    """
    计算答案置信度
    
    因素：
    1. 文档数量（更多文档 = 更高置信度）
    2. 文档质量（长度、相关性）
    3. 文档多样性
    """
    if not documents:
        return 0.0
    
    # 基础分（基于数量）
    base_score = min(len(documents) / 5, 1.0) * 0.5
    
    # 质量分（基于平均长度）
    avg_length = sum(len(d.page_content) for d in documents) / len(documents)
    quality_score = min(avg_length / 500, 1.0) * 0.3
    
    # 多样性分
    diversity_score = 0.2
    
    return min(base_score + quality_score + diversity_score, 1.0)
```

## 7. 性能优化建议

### 7.1 Embedding 优化
- 使用 GPU 加速（device="cuda"）
- 增大批处理大小（batch_size=64）
- 使用更小的模型（bge-base-zh）

### 7.2 检索优化
- 使用 IVF 索引替代 Flat 索引
- 启用缓存（Redis/Memcached）
- 预计算热点查询

### 7.3 生成优化
- 限制上下文长度（max_context_length=3000）
- 使用流式输出
- 实现上下文压缩
